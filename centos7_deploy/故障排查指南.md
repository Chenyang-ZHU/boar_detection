# 野猪检测服务 · 部署后故障排查指南

> 适用：CentOS 7 部署（在线 `install_centos7.sh` / 离线 `deploy_offline.sh`），以及 Jetson 部署。
> 排查顺序建议：**服务状态 → 日志 → 依赖/配置 → 接口 → 视频 → 资源**。

---

## 0. 一图排查顺序

```
服务能起来吗？ ──否──▶ 见 §1 服务起不来
   │是
健康检查 /health 正常吗？ ──否──▶ 见 §2 接口异常
   │是
图像接口正常吗？ ──否──▶ 见 §2.2
   │是
视频接口正常吗？ ──否──▶ 见 §3 视频相关
   │是
公网(ngrok)正常吗？ ──否──▶ 见 §4 网络/公网
   │是
观察资源(内存/磁盘) ──▶ 见 §5 资源
```

## 1. 服务起不来（启动失败）

### 1.1 快速判断

```bash
systemctl status boar_detection          # 看状态和最近错误
journalctl -u boar_detection -n 50       # 看完整启动日志
```

| 现象 | 原因 | 处理 |
|------|------|------|
| `Active: failed` / `activating` | 启动崩溃或循环 | 看日志定位，见下 |
| 端口 5000 被占用 | 其他进程占了 | `ss -ltnp \| grep 5000`，杀掉冲突进程 |
| `ModuleNotFoundError: No module named 'xxx'` | 依赖没装全 | 装 `xxx`（如 waitress/qtfaststart/imageio-ffmpeg） |
| `ImportError: libstdc++.so.6 GLIBCXX_3.4.21 not found` | **系统 libstdc++ 太老** | `export LD_LIBRARY_PATH=/opt/miniconda3/envs/boar/lib`（systemd 已配，手动启动要加） |
| 模型加载失败 | best.pt 缺失/损坏 | 确认 `/opt/boar-detection/best.pt` 存在且 >1MB |
| 启动后立刻退、反复重启 | 崩溃循环 | 看日志；`StartLimitBurst=5` 5 次后停止 |

### 1.2 崩溃循环排查

```bash
# 看最近重启原因
journalctl -u boar_detection --since "10 minutes ago" | grep -E "error|Traceback|Failed|Killed" 
# 看系统 OOM（内存被杀）
dmesg | grep -i "killed process" | tail
free -h    # 内存是否耗尽
```

### 1.3 CentOS 7 特有坑（必查）

- **Miniconda 版本**：必须 `23.10.0-1`（`latest` 需 glibc≥2.28 装不上，报 "Installer requires GLIBC >=2.28"）
- **/dev/null 权限**：如果 `pip`/重定向报 `Permission denied: /dev/null`，说明 /dev/null 被改坏了（不是字符设备）：
  ```bash
  sudo rm /dev/null && sudo mknod -m 666 /dev/null c 1 3
  ```
- **yum 装不上系统包**：CentOS 7 已 EOL，源需切 vault（见 README）

## 2. 接口异常

### 2.1 健康检查

```bash
curl http://127.0.0.1:5000/health
# 正常: {"status":"ok","device":"cpu","model_loaded":true,"busy_requests":0,...}
```

| 现象 | 原因 | 处理 |
|------|------|------|
| `connection refused` | 服务没起来 / 重启中 | 等几秒重试；服务起不来见 §1 |
| `device: "cpu"`（期望 cuda） | Jetson 上 DEVICE 没配 | 检查 config.py `DEVICE="cuda:0"` |
| `busy_requests` 长期 >0 | 有请求卡住/断开没释放 | 等处理完；信号量会自动释放 |

### 2.2 图像/视频接口错误码

| code | 含义 | 排查 |
|------|------|------|
| `40001` | 参数错误：格式/尺寸/时长/缺字段 | 看 message：图片长边>8192 / 视频>300s / 非 mp4/avi/mov |
| `429001` | **服务繁忙**（并发超限 4） | 同时请求太多，退避重试；若一直繁忙查是否有卡死请求 |
| `50001` | 模型推理异常 | 看日志的 Traceback；常见 CUDA OOM / 模型损坏 |
| `50002` | 处理超时（图像30s/视频180s） | 视频太大/太长；或 CPU 太慢，调大 config 超时 |

### 2.3 图片上传后返回空/失败

- 图片必须 JPEG/PNG/BMP（按文件头识别，不看扩展名）
- 长边 ≤ 8192px、大小 ≤ 50MB
- 上传方式：multipart `-F "image=@文件"`（**必须有 @**，否则当字符串）

## 3. 视频相关（重点）

### 3.1 浏览器播放不了

| 现象 | 原因 | 处理 |
|------|------|------|
| 视频跳下载、不播放 | 编码是 **mp4v（MPEG-4 Part 2）** | 检查编码（见下）；H.264 才能播 |
| 不能边下边播/不能拖动 | **moov 在文件尾部** | 检查 moov 位置；应在前 |

**检查输出视频编码和 moov 位置：**
```bash
# 下载视频后检查
python3 - << 'EOF'
b = open("out.mp4","rb").read()
print("H.264(avcC):", b.count(b"avcC"), "| MPEG4(mp4v):", b.count(b"mp4v"))
import struct
pos, ats = 0, []
while pos < len(b) and len(ats) < 5:
    s, t = struct.unpack(">I4s", b[pos:pos+8])
    if s == 0: break
    ats.append(t.decode()); pos += s
print("atom:", "->".join(ats), "| moov前置:", "OK" if ats[1]=="moov" or "moov" in ats[:2] else "FAIL")
EOF
```
- 期望：`H.264(avcC)=1`、`mp4v=0`、`atom: ftyp->moov->free->mdat`
- 如果输出是 mp4v：说明 **imageio-ffmpeg 没装或 libx264 不可用** → `pip install imageio-ffmpeg==0.6.0`，重启服务

### 3.2 画框视频"没有检出"（没画框）

先确认是**没检出**还是**画框丢了**：
```bash
# 用同一个视频调坐标接口
curl -X POST .../detect/video/coords -F "video=@test.mp4"
# 看 data.total_detections / data.max_detections
```
- **坐标接口也返回 0** → 是模型没检出（置信度 < 0.25 被过滤）。处理：调低 `CONFIDENCE_THRESHOLD`（如 0.1）
- **坐标接口有，但画框视频没框** → 异常，重新部署/看日志

### 3.3 视频接口超时

- CPU 推理慢：视频逐帧 ~50-150ms/帧，30s@30fps 视频约需 1-2 分钟
- 调用方超时：视频接口建议 **180s+**
- 服务端 `VIDEO_PROCESS_TIMEOUT=180` 是硬上限，超时返回 50002

## 4. 网络 / 公网（ngrok）

### 4.1 局域网不通

```bash
ping <服务器IP>
curl http://<服务器IP>:5000/health
```
- 防火墙：`systemctl stop firewalld`（或放行 5000 端口）
- 服务监听：确认 `ss -ltnp | grep 5000` 是 `0.0.0.0:5000`

### 4.2 公网（ngrok）不通

| 现象 | 原因 | 处理 |
|------|------|------|
| 404/503、间歇 | ngrok 隧道断线 | 检查 `systemctl status ngrok`；region 用 ap |
| 传大视频后失败 | **免费版月度 1GB 带宽耗尽** | 用局域网；或等额度恢复 |
| 浏览器弹免费提示页 | ngrok 免费版拦截 | 用 curl/Python 不受影响 |

### 4.3 调用方浏览器跨域读不到 X-Boar-Count

- 浏览器跨域默认读不到自定义响应头
- 需服务端加 CORS：`Access-Control-Expose-Headers: X-Boar-Count`
- 后端调用不受影响

## 5. 资源类问题

### 5.1 内存不足

```bash
free -h
# 服务占用
ps -o pid,rss,cmd -C python | grep app.py
```
- Jetson 只有 3.5GB，并发视频易 OOM → 减少并发（MAX_INFERENCE_WORKERS）
- OOM 表现：服务被杀重启、请求 500

### 5.2 磁盘满

```bash
df -h /
# journald 占用（日志暴涨）
journalctl --disk-usage
# 视频临时文件残留
ls -la /tmp/boar_detect_* /tmp/boar-*.mp4 2>/dev/null
```
- journald 已限 500M（部署脚本配置）
- 临时文件 cron 每 30 分钟清理

### 5.3 端口占用

```bash
ss -ltnp | grep 5000
```

## 6. 自愈机制说明（应该自动恢复）

| 故障 | 自愈机制 |
|------|---------|
| 进程崩溃 | systemd `Restart=always`，5s 后重启 |
| 进程活着但卡死 | cron 健康探活（每分钟）→ 探测失败 → `systemctl restart` |
| 反复崩溃 | `StartLimitBurst=5` 后停止（防循环刷日志）→ 需人工看日志 |

> 如果服务"自己好了"，多半是自愈在起作用；日志 `/var/log/boar_health.log` 记录健康探活的恢复动作。

## 7. 已知坑点速查（CentOS 7）

| 坑 | 症状 | 解决 |
|----|------|------|
| Miniconda latest 装不上 | "Installer requires GLIBC >=2.28" | 用 `23.10.0-1` |
| libstdc++ 太老 | GLIBCXX_3.4.21 not found | `LD_LIBRARY_PATH=/opt/miniconda3/envs/boar/lib` |
| /dev/null 被改坏 | pip/重定向 Permission denied | `mknod -m 666 /dev/null c 1 3` |
| 升级依赖 | 装不上/起不来（numpy2/torch2.7/opencv4.10） | 钉旧版，别升级 |
| yum 源 404 | CentOS 7 EOL | 切 vault.centos.org |
| mp4v 编码 | 浏览器不播 | 装 imageio-ffmpeg（H.264） |
| moov 在尾部 | 不能流式 | qtfaststart/imageio-ffmpeg faststart |
